**Decisions (Brandon, 2026-10-27):**
1. "I want 'inspect' in the same group as 'examine', 'search', 'check', etc. What it should do is restate the same thing about the gap in the drawer frame."
2. "I want it to repeat the nudge about the drawer gap if the player is interested in the drawer, so it pushes them to try something else."
3. "I want to gate on 'look under' not just 'look'. Obviously the 'under' goes for the other verbs as well: examine, search, etc."
4. "look inside should open the drawer. It has to. (if it isn't open already)"
5. "You can rewrite the story data for the drawer nudge." and "I told you that you can write the story in this case, not ChatGPT (for the nudge text)."

## Why

In the T9b full run all 7 unsuccessful turns (6 of 80 on route A, 1 of 20 on route B) were `inspect the drawer`, request kind `open` (Jev answered `opens_container` true on 14 of 15 such turns). Kind `open` adds the conditional line "If the drawer opens, show what is inside it". In each failure the narrator set the drawer `"state":"open"` in `item_facts` while its prose only said Kristin "decides to open it", so the world became open and the four supplies were never shown. Under Brandon's rules `inspect the drawer` is not an opening command, so it must be kind `look` on a closed drawer: nothing inside is required and the conditional line never appears. `look inside the drawer` is an opening command and "has to" open it, so the world must really be open afterwards with the supplies shown. Nothing in the engine opens a container today (the world opens only if the narrator writes it), so the engine performs that step itself (decision W12; memory `engine-performs-prerequisite-steps`). The story already has the nudge Brandon wants (`k_sl_1a_f_r2`: "The drawer rides high in its frame. A thin gap beneath its lower edge is wide enough for Kristin's fingers."), but its evidence needs the words "initials" or "carving" and it can fire only once.

## The change (fixed now)

**1. Jev wording (code, Ringer).** `opens_container` in `storygame/runtime/jev_questions.py` is reworded so that opening, and saying inside, in, into or through, count, and looking at the outside does not (the same rule as `searches_underneath`: the command must say the word):
- instructions: `Decide whether the command has the player open the container. Opening it, pulling it open or out, or going inside, in, into, or through it counts.`
- true: `The command opens the container, pulls it open, pulls it out, or says inside, in, into, or through the container. The player looks, feels, or reaches there.`
- false: `The command does not open the container and does not say inside, in, into, or through. A command that only looks at, inspects, examines, searches, checks, closes, locks, touches, moves, carries, or talks about the container, or goes under, behind, or on top of it, is false.`
Function name, signature, return type and the `noul` type are unchanged. `searches_underneath` is unchanged (T9b probe 2 passed it). The wording follows `docs/jev-guard-rules.md` and was written from Brandon's rule and the T9b failure class only. The lists below were written after it. None of them has been run, and none of their commands appears in an earlier probe's list except the labelled regression set.

**1b. The engine opens the container (code, Ringer; story-agnostic).** In `WorldCapture._set_observation_request`, when the kind comes out `open`, the focus is openable and closed, and the protagonist can see it (`world.sees`), the engine calls `world.set_axis(focus, "open")` before the narrator is called. Nothing else moves. No sentence is authored for the opening; the narrator learns of it because the world now shows the contents, so the duty line "Show these in your reply: ..." applies (the conditional "If the X opens, show what is inside it" no longer applies). The step is a no-op on an open container ("if it isn't open already"), on a container that is not openable, on kinds `look`, `under` and `enter`, and when Jev answers false or unknown. The engine's whole-turn snapshot is taken before `capture.before_turn` and restored on every failure path, so an engine open rolls back like a boarding step; the harness records the container's open state after every turn so this is checked, not assumed. `observe_automatically` is True by default, so the step runs in the product whether or not `FREYTAG_OBSERVATION_ENFORCE` is set (that switch only turns on the verifier). Only `is_openable`, the axis and `sees` are used: no names, verbs or story strings in engine code.

**2. A repeatable knowledge entry (code, Ringer; story-agnostic).** `KnowledgeDefinition` gains `repeatable: bool = False`. A repeatable entry, after its effects already hold, is still an eligible reveal: `explain_reveal` (`reveal_eligibility.py`) and `_eligible_reveal_candidates` (`cloudflare.py`) skip the already-established and storylet-spent checks for it. Every other rule still applies (`requires`, audience, `reach_entity_ids`, scene, evidence). The authored `delivery_text` is appended after the narration each time it matches. No names, verbs or story strings enter engine code.

**3. A specific match wins (code, Ringer; story-agnostic).** `uniquely_matched_authored_handoff` returns nothing today when two entries match one command. The new nudge (verb x drawer) and the card find (verb x under-word x drawer) both match `look under the drawer`. When more than one entry matches in full, the entry with the most evidence groups wins; a tie still returns nothing. This ranks only complete matches, never partial ones, and uses no vocabulary.

**4. Story data (I write it; no ChatGPT round).** In `data/stories/continuity-initiative/knowledge.yaml`, `k_sl_1a_f_r2` is rewritten in place (same id and source):

- `action_evidence`: `[[examine, inspect, search, check, look, study, read, trace, run my fingers], [drawer, "drawer's", KMS, initials, carved initials, carving, my initials]]` (the old initials wording stays, so examining the carved initials still earns it) (the matcher's synonym class already adds feel, investigate, look at and the rest).

The synonym classes make examine, feel, study and the rest count as the verb too, and below, underneath and underside count as the under word; a test pins this for each verb.

## Stage P: Jev classification probe (billed, tiny)

**Grid (the "under goes with every verb" gate).** Verbs: Inspect, Examine, Search, Check, Look at. Containers: cabinet, chest, locker, toolbox. Three forms per verb and container: bare (`Inspect the cabinet.`, `Look at the chest.`) and under (`Inspect under the cabinet.`, `Examine beneath the locker.`, `Search underneath the toolbox.`, `Check below the cabinet.`; the verb `Look at` becomes `Look under` in its under form) and inside (`Inspect inside the cabinet.`, `Examine inside the chest.`, `Search inside the locker.`, `Check inside the toolbox.`; the verb `Look at` becomes `Look inside`). The generator rotates under, beneath, underneath and below across the cells in a fixed order and records the result in the corpus lock. 5 verbs x 4 containers x 3 forms = 60 commands. Each is asked both `opens_container` and `searches_underneath`.

A pass does not deploy anything and does not turn the hosted switch on; it permits writing the T9 confirmation preregistration. A fail on N1, N2 or N3 or on clause 1 is a stop with the rows and labels recorded.

**Expected, not measured.** N1 close to 75 of 75 if inspect stops being kind `open`: the 20 `feel under the drawer` turns in the T9b run (kind `under`) and the 15 `pull out the drawer` turns all committed first try. N2 follows from a deterministic match once the specific-match rule works, and the free tests must show that before any billed call. Risks I can see: Jev may still answer `opens_container` true for some inspect phrasings (the wording was written from the failure class); the narrator may open the drawer itself in `item_facts` on a look turn and then omit the supplies, which would repeat the T9b failure under kind `look` (the supplies would then be required by the verifier, because the container became open); the narrator may set the drawer closed in `item_facts` after the engine opened it (T9b rows show `"state":"closed"` on 3 of 10 route A inspect turns), which would leave the world closed with nothing required, so `look inside` would not hold; Jev may answer true for bare `search the drawer` because "search" can read as "search inside", which the grid and the regression set test; `look` is in the same synonym class as feel, so `feel the drawer` with no under word will now earn the nudge, which I think is intended; the first delivery of the nudge in a turn that the card find also matches depends on the new specific-match rule working in the live path, not only in unit tests.

**Stated limits.** One story, 70B only, one reader who knows the aim, ten route A replicates share one start (routes B and C share it too). The phrase lists are small and hand-made; a pass shows the wording works on them, not on all player language, and says nothing about pronoun commands ("inspect it"). Unlocking, keys and locked containers are out of scope. The engine step adds no "she opens it" sentence, so a player who looks inside a closed drawer reads about its contents without an explicit opening line unless the narrator writes one; whether to add authored open text to the story package is a separate story-content decision. The nudge text is repeated verbatim by design; players who keep inspecting will see the same two sentences each time, and whether that reads as a hint or as nagging is a story judgement this run does not measure.
